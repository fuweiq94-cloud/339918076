## 简介
本指南面向 ProcessModules 框架的构建与部署，覆盖开发环境搭建、解决方案配置、独立 DLL 构建、打包发布、CI/CD 流水线集成、部署策略以及生产监控与排障。目标是帮助开发者在本地与持续集成环境中稳定地编译、签名、打包并分发三个独立模块 DLL（MainControl、PointJump、Trajectory），确保版本兼容与可回滚能力。

**更新** 构建系统现已增强，支持多种编译方法：Visual Studio IDE图形界面、MSBuild命令行工具和dotnet CLI工具，为不同使用场景提供了灵活的构建选择。

### 多种编译方法支持

#### Visual Studio IDE 构建
- 打开解决方案文件 `ProcessModules.sln`
- 选择目标配置（Debug/Release）和平台（x86/x64/AnyCPU）
- 右键解决方案 → 生成
- 或使用快捷键 `Ctrl+Shift+B`

#### MSBuild 命令行构建
```bash
# 基本构建
msbuild ProcessModules.sln /p:Configuration=Release /p:Platform=x64

# 并行构建
msbuild ProcessModules.sln /m

# 清理后构建
msbuild ProcessModules.sln /t:Clean,Build
```

#### dotnet CLI 工具构建
```bash
# 还原依赖
dotnet restore ProcessModules.sln

# 构建解决方案
dotnet build ProcessModules.sln --configuration Release --platform x64

# 发布单个项目
dotnet publish MainControl/MainControl.csproj --configuration Release
```

**更新** 构建系统现已支持三种不同的编译方法，开发者可以根据使用习惯和自动化需求选择合适的构建方式。

## 故障排查指南
常见问题与定位方法
- 无法解析依赖：检查 NuGet 包还原与引用路径。
- 签名失败：确认证书有效性与权限。
- 运行时找不到模块：核对 DLL 输出目录与宿主加载路径。
- 版本冲突：使用绑定重定向或隔离加载域。
- 模块间版本不兼容：检查三个模块的版本协调配置。
- 构建失败：验证开发环境配置和工具链版本。

建议的日志与监控
- 应用日志：记录关键生命周期与错误堆栈。
- 系统指标：CPU、内存、I/O 监控。
- 告警规则：基于错误率与响应时间阈值。
- 模块健康检查：监控三个模块的加载状态和运行状况。

**更新** 故障排查指南现在包含了三个独立DLL特有的问题，如模块间版本冲突、加载顺序等问题，以及多种构建方法可能遇到的环境问题。
