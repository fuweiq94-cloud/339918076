# 工艺模块基类调整说明

## 📋 修改背景

### 问题发现

之前三个工艺模块都继承自 `ProcessModuleBaseEx`（本项目自定义的扩展基类），该类提供了以下额外功能：

```csharp
public abstract class ProcessModuleBaseEx : ProcessModuleBase
{
    public event EventHandler<ModuleAlarmEventArgs> AlarmOccurred;
    
    public virtual void SetMotionService(IMotionService service) { }  // ❌ 问题所在
    
    protected new void InsertAlarm(string message) { }
    protected string GetModuleVariable(...) { }
    protected void SetModuleVariable(...) { }
}
```

### 核心问题

**`SetMotionService` 方法在 `InterfaceDefine.dll` 的 `ProcessModuleBase` 中并不存在！**

这意味着：
- ❌ 使用 `override` 关键字会编译失败
- ❌ 平台无法调用这个方法（因为基类没有定义）
- ❌ 引入了不必要的依赖关系

---

## ✅ 解决方案

### 修改内容

将三个工艺模块的继承关系从：

```csharp
public class PointJumpProcessModule : ProcessModuleBaseEx  // ❌ 错误
```

改为：

```csharp
public class PointJumpProcessModule : ProcessModuleBase  // ✅ 正确
```

并删除 `SetMotionService` 方法。

## 🔍 为什么这样修改？

### 原因 1：避免编译错误

```csharp
// ProcessModuleBaseEx.cs
public abstract class ProcessModuleBaseEx : ProcessModuleBase
{
    public virtual void SetMotionService(IMotionService service) { }  // 虚方法
}

// PointJumpProcessModule.cs
public class PointJumpProcessModule : ProcessModuleBaseEx
{
    public override void SetMotionService(IMotionService service)  // ⚠️ 这里会报错
    {
        // ...
    }
}
```

**问题**: `ProcessModuleBase`（来自 InterfaceDefine.dll）中没有定义 `SetMotionService`，所以 `override` 会失败。

### 原因 2：保持与平台接口一致

平台只认识 `ProcessModuleBase` 中定义的方法：

```csharp
// InterfaceDefine.dll 中的 ProcessModuleBase
public abstract class ProcessModuleBase
{
    public abstract dynamic FunctionCaller { get; }
    public abstract string GetInfo();
    public abstract bool Init(string strName);
    public abstract bool LoadSetting();
    public abstract bool Save();
    public abstract bool ShowRunForm(Panel panel);
    public abstract bool ShowSettingForm(Panel panel);
    public abstract int Action(params object[] param);
    public abstract bool SetParam(object sKey, object sValue);
    public abstract object GetParam(object itemName);
    public abstract bool StopAll();
    public abstract bool ReleaseAlarm();
    public abstract bool ReOpen();
    public abstract bool Close();
    
    // ❌ 没有 SetMotionService！
}
```

### 原因 3：简化依赖关系

**修改前**:
```
PointJumpProcessModule
    ↓ 继承
ProcessModuleBaseEx (本项目)
    ↓ 继承
ProcessModuleBase (InterfaceDefine.dll)
```

**修改后**:
```
PointJumpProcessModule
    ↓ 继承
ProcessModuleBase (InterfaceDefine.dll)
```

✅ 减少了一层不必要的继承

## ⚠️ 影响分析

### 失去的功能

删除 `SetMotionService` 后，以下功能不再可用：

```csharp
// ❌ 不能再这样调用
module.SetMotionService(myMotionService);
```

### 替代方案

如果需要注入运动控制服务，可以使用以下方式：

#### 方案 1：通过构造函数注入

```csharp
public class PointJumpProcessModule : ProcessModuleBase
{
    private XyzControllerHub _hub;
    
    // 添加构造函数
    public PointJumpProcessModule(IMotionService service = null)
    {
        _hub = new XyzControllerHub(service, ...);
    }
}
```

#### 方案 2：通过属性设置

```csharp
public class PointJumpProcessModule : ProcessModuleBase
{
    private XyzControllerHub _hub;
    
    // 添加公共属性
    public IMotionService MotionService
    {
        set { _hub?.SetService(value); }
    }
}

// 使用
var module = new PointJumpProcessModule();
module.MotionService = myService;
```

#### 方案 3：在 Init 中初始化

```csharp
public override bool Init(string strName)
{
    // 从配置或平台获取服务
    IMotionService service = GetMotionServiceFromPlatform();
    _hub = new XyzControllerHub(service, ...);
    
    return base.Init(strName);
}
```

## 🎯 最佳实践建议

### 1. 何时使用 ProcessModuleBase？

✅ **推荐场景**:
- 只需要实现平台定义的标准接口
- 不需要额外的扩展功能
- 希望保持与平台的最大兼容性

### 2. 何时使用 ProcessModuleBaseEx？

⚠️ **谨慎使用**:
- 确实需要 Alarm 事件机制
- 需要统一的变量管理方法
- 明确知道这些扩展不会与平台冲突

### 3. 如何安全地扩展？

如果确实需要扩展功能，建议：

```csharp
public class PointJumpProcessModule : ProcessModuleBase
{
    // ✅ 添加新属性（不是 override）
    public event EventHandler<ModuleAlarmEventArgs> CustomAlarm;
    
    // ✅ 添加新方法（不是 override）
    public void SetCustomMotionService(IMotionService service)
    {
        _hub?.SetService(service);
    }
    
    // ✅ 实现平台定义的抽象方法
    public override dynamic FunctionCaller
    {
        get { return this; }
    }
}
```

- 避免误用

**缺点**:
- 如果有其他代码引用会报错

## 🎉 总结

通过本次修改：

✅ **消除了编译错误风险** - 不再 override 不存在的方法  
✅ **简化了继承层次** - 直接继承平台基类  
✅ **提高了兼容性** - 与平台接口保持一致  
✅ **降低了耦合度** - 减少了对本项目扩展类的依赖  

**核心原则**: 
> 只实现平台定义的接口，不添加平台不认识的方法。
