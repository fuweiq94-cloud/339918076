# 命名空间与类名一致性最终验证报告

## 📋 验证背景

根据平台软件的反射调用机制，**命名空间必须与类名完全一致**，这样才能通过简单的字符串映射找到并实例化模块。

### 平台调用原理

```csharp
// 平台通过完整类型名加载模块
string typeName = "命名空间。类名";  // 例如："PointJumpProcessModule.PointJumpProcessModule"
Type type = Assembly.Load("ProcessModules").GetType(typeName);
object module = Activator.CreateInstance(type);
```

**关键要求**: 命名空间 = 类名，这样平台只需要知道类名就能构造出完整类型名。

## 📊 命名规范总结

### 核心规则

```
命名空间 = 类名 = 模块名 + "ProcessModule"
```

### 完整类型名构造

```
完整类型名 = 命名空间。类名
           = 类名。类名
           = (模块名 + "ProcessModule") + "." + (模块名 + "ProcessModule")
```

### 示例

| 模块名 | 类名 | 命名空间 | 完整类型名 |

| MainControl | MainControlProcessModule | MainControlProcessModule | MainControlProcessModule.MainControlProcessModule |

## 🔧 常见问题

### Q1: 为什么命名空间要和类名一致？

**A**: 平台通过反射加载模块时，需要完整的类型名（命名空间。类名）。如果命名空间=类名，平台只需要知道类名就能构造出完整类型名，简化了配置和调用。

### Q2: 如果命名空间和类名不一致会怎样？

**A**: 平台无法通过简单的字符串映射找到类，需要额外的配置来指定完整的类型名，增加了复杂度。

### Q3: 新增模块时应该如何命名？

**A**: 遵循以下规则：
```csharp
// 假设新模块名为 "NewModule"
namespace NewModuleProcessModule  // 命名空间 = 模块名 + ProcessModule
{
    public class NewModuleProcessModule : ProcessModuleBase  // 类名 = 模块名 + ProcessModule
    {
        // ...
    }
}
```

### Q4: 为什么 Trajectory 模块的类名是 TrajectoryViewProcessModule 而不是 TrajectoryProcessModule？

**A**: 这是历史原因，该模块最初设计为"轨迹查看"功能，所以类名包含了"View"。为保持一致性，命名空间也使用了相同的名称。
